Codex 使用经验分享

这份 PDF 是 Codex 使用经验的详细版，整理了实际踩过的坑、可行的配置路径、项目迭代方法和安全边界，方便后续按步骤查看。

01 / Codex 和 ChatGPT 的区别

ChatGPT 更像问答窗口，Codex 更像项目协作者

网页版 ChatGPT

  • 适合解释概念、写文案、头脑风暴。
  • 主要依赖使用者手动复制上下文。
  • 回答之后，通常还需要手动打开文件继续操作。

Codex

  • 可以读取本地项目里的 PRD、原型记录、日报、素材和页面文件。
  • 可以在授权范围内修改文件、启动检查、打开页面查看结果。
  • 适合把一个任务从“想法”推进到“可用产物”。

理解重点：Codex 不只是更会聊天，而是能拿到项目上下文，并围绕上下文执行一串动作。

02 / 从聊天到动手做事

先体验 1-6：一条典型工作链路

1

听懂需求

先确认目标、对象、交付物和限制条件。

2

读取材料

读取 PRD、原型、历史日报、截图和现有页面。

3

制定步骤

拆解任务，明确先做什么、后检查什么。

4

调用工具

打开页面、处理图片、读取文件、生成资料。

5

产出资料

输出文档、页面、清单、PDF 或可查看版本。

6

验证再修

检查展示效果、文案一致性、遗漏点和边界问题。

Plugin / Skill / MCP

后了解 Plugin、Skill、MCP：把链路扩展开

Plugin

把一组能力打包成可调用的工具。比如浏览器检查、图片生成、文件处理、页面检查。

Skill

把反复使用的做法沉淀成稳定流程。比如整理文档时，先读资料、统一口吻、检查页面。

MCP

把外部工具接入工作链路。比如 Photoshop、Figma、知识库、工单系统或内部资料源。

安装方式

装好 Codex 后，很多扩展不需要手动下载安装。说明要接入的工具，它可以协助配置。

产品和设计的重点：先跑完一次真实任务，再回头理解这些扩展词，会比一开始背概念更自然。

03 / 两个实操案例

AI 怎么进入真实项目

不止是代码：读文件夹给建议

把 PRD、日报、截图和页面文件放在项目里，让 AI 先看现状，再指出信息缺口、体验风险和下一步优化。

Vibe coding 初体验：现场互动系统

从“观众扫码发弹幕、送礼物、演讲端实时展示”开始，一边描述想要的效果，一边让 AI 搭出可运行版本。

关键经验：不用先把所有方案想完整，可以边试、边看、边改，让项目自己长出来。

04 / 安装与避坑

路径一：官方省心版

准备账号

准备可以正常登录的 Google 账号，以及本人可长期接收短信验证的手机号。

官方订阅

优先走官方订阅和官方客户端，入口、权限、模型体验和后续更新都更稳。

美区 App Store

如果手机端订阅入口更顺，可以准备美区 Apple ID，通过 App Store 订阅，再和电脑端登录账号联动使用。

多端联动

官方路径的好处是体验更完整，电脑端和手机 App 可以形成联动，也更少遇到配置兼容问题。

手机号问题

如果手机号无法验证，优先更换本人可用号码或正规长期号码。公共接码平台不建议用于重要账号验证。

电脑安装

Mac 可以直接安装 Codex；Windows 桌面版需要通过 Microsoft Store 安装。公司电脑如果默认关闭商店权限，可以请 IT 临时打开。

04 / 安装与避坑

路径二：省钱但有风险版

1

先装 Codex

客户端还是要先装好。Mac 直接安装；Windows 走 Microsoft Store，公司电脑可能要请 IT 临时放开权限。

2

准备 API Key

从 DeepSeek、模型服务商或中转站拿到 Key。先确认余额、额度、可用模型、网络连通性和是否兼容 OpenAI 风格接口。

3

用 cc switch 切配置

cc switch 的作用是管理不同 API 地址、Key 和模型配置，方便在官方、DeepSeek 或中转站之间切换。

4

先跑测试任务

导入配置后，先用非敏感小任务测试响应速度、工具调用、长上下文和代码修改效果，再决定是否用于正式工作。

注意：这条路便宜，但不是“免费省心版”。API Key 会把请求发到对应服务或中转站，稳定性、隐私、模型质量、计费和封号风险都要自己承担。它适合折腾和非敏感任务，不建议直接处理客户资料、内部机密或重要账号。

补充经验

省钱路线一定要确认四件事

Key 和账号安全

API Key 等同于花钱权限，不要随手发群里或写进公开文件。共享账号、临时邮箱、公共接码都不适合作为长期主方案。

数据会去哪里

中转站会经过额外服务链路。敏感文档、客户数据、内部资料先脱敏，或者只用官方路径和测试材料。

服务是否稳定

确认余额、额度、模型支持、网络质量和高峰期响应。便宜路线常见问题是变慢、断流、模型不可用。

模型质量是否够用

同名模型也可能有不同接入质量。先用小任务测试代码修改、文件读取、工具调用和长上下文，再放进正式流程。

安全边界

让 AI 做事之前，要先讲清楚边界

哪些能看

明确哪些资料可以读取，哪些账号、私密文档、客户数据不能碰。

哪些能改

明确哪些文件可以修改，哪些资料只能作为参考，不能直接覆盖。

哪些要确认

安装软件、上传文件、改权限、删除资料、发布内容前，都应该让人确认。

人仍然负责判断

AI 可以提高效率，但最终判断、取舍和风险责任仍然在人。

最后

最后留下两句话

AI 是增强人的工具，不是替代人的判断；越会用它，越要保持清醒和边界。

依靠 AI，但不依赖 AI

用 AI 武装自己，保持学习、理解原理、训练判断力，让它放大能力，而不是替代思考。

坚守信息安全红线

账号、客户资料、内部文档和敏感数据都要守住边界；能不能给 AI 看，先按安全要求判断。
